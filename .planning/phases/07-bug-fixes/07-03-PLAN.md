Add AbortController-based cancellation to workerPool.js per the context decision:
- Use AbortController for cancellation signaling (Web standard)
- Accept all completions regardless of order (race conditions acceptable)
- Log cancellations for diagnostic purposes

Changes to workerPool.js:

1. Add activeRequests Map to track in-flight requests with AbortControllers:
```javascript
this.activeRequests = new Map(); // callbackId -> { abortController, message, priority }
```

2. Modify enqueueTask to create AbortController for each request:
```javascript
const abortController = new AbortController();
this.activeRequests.set(callbackId, { abortController, message, priority });
```

3. Add cancelRequest(callbackId) method:
```javascript
cancelRequest(callbackId) {
  const request = this.activeRequests.get(callbackId);
  if (request) {
    request.abortController.abort();
    this.activeRequests.delete(callbackId);
    this.pendingCallbacks.delete(callbackId);
    if (DEBUG) console.log(`[WorkerPool] Cancelled stale request ${callbackId}`);
    return true;
  }
  return false;
}
```

4. Add cancelStaleRequests(camChunkX, camChunkZ, maxDistance) method that:
   - Checks each active request against current camera position
   - Cancels requests for chunks beyond maxDistance
   - Returns count of cancelled requests
   - Logs each cancellation at DEBUG level

5. Handle AbortError in handleWorkerResponse (ignore abort errors):
```javascript
// AbortError means request was cancelled - ignore it
if (error.message && error.message.includes('aborted')) {
  return;
}
```

6. Clean up activeRequests when worker completes (remove entry)
