<task type="auto">
  <name>Ensure immediate WebGL mesh sync after block edit</name>
  <files>voxx-js/src/blockEditor/BlockEditor.js</files>
  <action>
In BlockEditor.js, after block edit operations (destroyBlock and placeBlock), the code currently:
1. Sets voxel data
2. Generates mesh data
3. Clears old WebGL mesh

The missing step: call syncChunkToWebGL(chunk) immediately after clearing the mesh to recreate it in the same frame.

In destroyBlock() method (around line 154), after `this.clearChunkWebGLMesh(chunk)`, add:
```javascript
// Immediately recreate WebGL mesh
this.syncChunkToWebGL(chunk);
```

In placeBlock() method (around line 199), after `this.clearChunkWebGLMesh(chunk)`, add the same call.

This ensures the WebGL mesh is recreated synchronously after the block edit, not waiting for the next render frame.
  </action>
  <verify>npm test -- tests/ 2>/dev/null || echo "Build test only - manual verification needed"</verify>
  <done>WebGL mesh recreated immediately after block edit</done>
</task>

<task type="auto">
  <name>Update neighbor chunks immediately at boundaries</name>
  <files>voxx-js/src/blockEditor/BlockEditor.js</files>
  <action>
The markNeighborChunksForUpdate() method marks neighbor chunks but only regenerates their mesh data, it doesn't recreate the WebGL mesh. After block edits at chunk boundaries, neighbor chunks need their WebGL meshes recreated too.

In markNeighborChunksForUpdate(), after updating meshData for each neighbor:
```javascript
if (neighborChunk && neighborChunk.hasVoxelData) {
  neighborChunk.meshData = neighborChunk.generateMeshData();
  neighborChunk.needsUpdate = true;
  // Recreate WebGL mesh for neighbor chunk
  this.syncChunkToWebGL(neighborChunk);
  if (DEBUG) console.log(`[BlockEdit] Marked neighbor chunk ${n.x},${n.z} for update`);
}
```
